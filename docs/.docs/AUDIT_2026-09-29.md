# Security and quality audit — 2026-09-29

Scope: full audit of the payconnectoid core server (`src/`, `app/`, `convex/`, `tests/`,
`openapi.yaml`) covering security, correctness, and developer/user experience.

Baseline before this audit: `npm run verify` green, 23 tests passing.
Baseline after: `npm run verify` green, 37 tests passing.

## Fixed in this pass

### 1. SSRF via outbound webhook subscriptions — high

`src/events/delivery.js` called `fetch(subscription.url, …)` with no validation of the
target. The URL is supplied by any caller holding `write` scope
(`POST /api/v2/webhook-subscriptions`), so a caller could direct the server at cloud
metadata (`169.254.169.254`), loopback services, or internal hosts, and read the response
through delivery records.

Added `src/net/url-guard.js` and wired it into create, update, and delivery. Redirects are
now `manual`. Covered by `tests/webhook-url-guard.test.js` (7 tests).

### 2. Blocking `scryptSync` on the login path — high

`src/auth/passwords.js` used the synchronous `scryptSync`, so each login attempt blocked
the whole event loop for the full key-derivation cost. On a public auth endpoint that is a
serialized denial-of-service primitive as well as a latency problem.

`hashPassword`/`verifyPassword` are now async. The stored hash format and every
verification outcome are unchanged; only scheduling changed. `app/server.js` seeds and
normalizes state asynchronously to match.

### 3. Username enumeration by response timing — medium

`POST /api/auth/login` skipped password verification entirely when the username did not
exist, so a miss returned in microseconds while a hit paid full scrypt cost. Unknown
usernames now burn equivalent derivation time via `burnVerificationTime`.

### 4. Silent rounding of money amounts — medium

`amountToMinor` converted via `Math.round(amount * 100)`, so values that cannot be
represented in minor units were silently coerced — `8.115` became `811`, `1.005` became
`100`. Silent rounding is a reconciliation-dispute generator.

Amounts are now exact-or-reject: decimal strings convert exactly, and any amount with more
precision than the minor unit is rejected as a validation error rather than guessed.
Covered by `tests/auth-and-money.test.js`.

### 5. `__proto__` corruption in analytics aggregates — low

`refundAnalytics`, `deliveryAnalytics`, and `reconciliationData` accumulated into plain
`{}` objects keyed by provider-, currency-, and event-derived strings. A key of `__proto__`
silently discarded its count and coerced the accumulator to a string. These now use
`Object.create(null)`.

### 6. Unhandled rejection in the delivery queue — low

`void processLoop()` had no rejection handler, so a failing `saveState` inside the loop
produced an unhandled rejection. The loop now reports through the dead-letter path.

### 7. Risk scoring accepted malformed amounts — medium

`POST /api/ai/risk-score` passed the payload straight to the scorer. A non-numeric amount
made every comparison false, producing `riskScore: 0` and the recommendation
"Risk appears low. Proceed normally." The route now validates the amount and returns
`400 VALIDATION_ERROR`. A risk engine that clears garbage is worse than one that refuses.

### 8. Broken repository links — trivial

`package.json` and `SECURITY.md` pointed at `LehroSolutions/payconnectiod` (missing `t`),
so the npm metadata, homepage, issue tracker, and security-reporting URL all 404'd.

## Documented, not changed — needs sign-off

`AGENTS.md` requires human approval before changing idempotency, webhook-signing, or
auth/token semantics. These are recorded in `SECURITY.md` under Known Limitations rather
than altered:

- Idempotency in-flight window allows a concurrent duplicate to reach the provider.
- A key stays `reserved` after a 422, blocking corrected retries.
- Unbounded growth of ledger, idempotency, trace, delivery, dead-letter, and audit arrays.
- `provider` is read from the untrusted body to select the signing secret.
- Legacy SHA-256 password hashes and a published constant `AUTH_SALT` default.
- Default `admin` / `admin123` credentials outside production.
- No login rate limiting or lockout.
- Subscription `secret` values are returned to `read`-scoped callers.
- DNS rebinding between the guard's lookup and `fetch`.
- `/api/ai/risk-score` declares no `authScope`.

## Open items outside this pass

- `convex/` mirrors the backend but is not referenced by `package.json`, has no
  dependency declared, and is not covered by `verify`. Its status is unclear.
- `docs/` carries three parallel trees (`docs/.docs/`, `docs/current/`, and top-level
  `docs/*.md`) plus generated `.html`/`.json` twins. `docs/.docs/SECURITY_ISSUES_2026-07-10.md`
  is a five-line stub that asserts no defects were found, which is misleading next to the
  findings above.
- `mcp_test.js` sits at the repository root, outside the `tests/` glob, so `npm test` never
  runs it.
- `verify` runs format and tests only; there is no lint or typecheck gate.
- `package.json` is `private: true` while carrying full publish metadata, `files`, and
  `exports` for a package named `payconnectoid-core`.
